## EXPLAIN

### 1. 두 가지 이상 후보

| 용어 | 뜻 | 대응 |
|---|---|---|
| 노이즈 | 한 번 튀고 곧 정상으로 돌아오는 일시적 값. 측정 오류·순간 외란일 수 있다 | 기록하고 지켜본다. 한 점의 이상치는 정비 신호가 아니다 |
| 추세적 상승 | 임계선을 향해 꾸준히 오르는 흐름 | **이 상승의 시작점**이 진짜 정비 신호 |
| 정비 필요 시점 | 추세적 상승이 시작된 시각 | "고장 전 계획 정비"의 기준점 |
| 임계선 (임계값) | 이 값을 넘으면 이상으로 보는 기준선. 오늘은 평상 범위 상한 | 차트에 가로선으로 그린다 |
| P-F 구간 | 징후가 처음 보이는 때(P)부터 기능 고장(F)까지의 시간 | 예지보전이 일할 수 있는 창 |

### 2. 한 점을 볼 것인가, 흐름을 볼 것인가

| 기준 | 임계선을 넘은 한 점만 본다 | 흐름의 시작점을 본다 |
|---|---|---|
| 노이즈 한 번 | "위험!" — 멀쩡한 설비에 인력 출동(오경보) | 바로 정상으로 돌아왔으니 지켜본다 |
| 꾸준한 상승 | 넘을 때까지 모른다 — 이미 P-F 구간 끝자락 | 오르기 시작한 때 안다 — 휴무일에 맞춰 계획 정비 |
| 결과 | 경보 피로, 늦은 대응 | 큰 사고를 작은 정비로 |

### 3. 케이스 — 베어링의 일생

회전체 베어링은 예고하고 고장 난다. ① 내부에 눈에 안 보이는 미세 손상이 생기고(사람은 모른다) → ② 진동이 추세적으로 오르고(숙련자는 어렴풋이, 진동 센서는 뚜렷이) → ③ 소리가 나고 온도가 오르고(누구나 안다) → ④ 파손돼 라인이 선다. ①~②와 ④ 사이의 시간이 P-F 구간이다. 원본 강의 사례에서도 한 제조사가 평소와 다른 미세한 진동 증가를 잡아 고장 직전에 부품을 바꿔 며칠 치 생산 손실을 막았다.

### 4. 원본 실습과제 2

원본 강의는 두 수열을 주고 "어느 쪽이 정비 신호인가"를 물었다. **[1.0 → 1.1 → 0.9 → 3.5 → 1.0]**과 **[1.0 → 1.3 → 1.7 → 2.2 → 2.9]**. 오늘 데이터를 보면 이 두 수열이 어디서 왔는지 알게 된다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
pdm-lab 폴더에서 이상 후보를 노이즈와 추세로 판정하고 대시보드 차트를 만들어 줘.

1. 입력: output/sensor_clean.csv, output/normal_range.csv, output/anomaly_candidates.csv. 없으면 멈추고 알려 줘.
2. 이상 후보마다 앞뒤 시점 값을 보고 "노이즈"(한 번 튀고 다음 시점에 평상 범위로 돌아옴)인지 "추세"(직전 두 시점부터 연속으로 오르다가 범위를 넘음)인지 판정해 줘.
3. 설비·변수마다 "상승 시작 시각"을 찾아 줘. 규칙: 첫 4시간(08:00~11:40, 12시점)을 기준 구간으로 잡고, 그 최댓값을 넘은 뒤 끝까지 다시 그 값 이하로 내려오지 않는 첫 시각. 그런 시각이 없으면 "없음".
4. 추세로 판정한 진동의 상승 시작 시각을 "정비 필요 시점"으로 정해 줘. 이상 후보는 없거나 늦게 나왔는데 상승 시작 시각이 있는 변수는 "범위 안 상승(추정)"으로 따로 적어 줘.
5. 판정 결과와 근거를 output/trend_judgement.md 에 [설비 / 변수 / 이상 후보 / 판정 / 정비 필요 시점 / 근거] 표로 적어 줘.
6. pdm-lab/index.html 을 만들어 줘. 외부 서버 없이 파일 하나로 열리게, 설비A·설비B 각각 진동·온도 선 차트를 그리고 평상 범위를 띠로, 이상 후보를 빨간 점으로, 정비 필요 시점을 세로선으로 표시해 줘. 맨 위에 "실습용 가상 데이터" 표시를 넣고, 휴대폰 화면에서도 가로로 넘치지 않게 해 줘.
7. 다 만들면 index.html 을 열어서 보여 줘.
```

### 확인할 것 (Phase B)

- `output/trend_judgement.md` 판정: 설비A 진동 12:40 3.5 → 노이즈, 설비B 진동 15:40 2.2·16:00 2.9 → 추세, 설비B 온도 16:00 65.1 → 추세.
- 설비B 진동 정비 필요 시점: 15:00.
- 범위 안 상승: 설비B 온도가 12:40부터 오르기 시작한 것이 따로 적혀 있다.
- 원본 실습과제 2의 두 수열이 각각 설비A 진동 11:40~13:00, 설비B 진동 14:40~16:00 구간 값이라는 것을 수강생이 차트에서 찾을 수 있다.
- `index.html`이 열리고 차트 4개(설비 2 × 진동·온도), 평상 범위 띠, 빨간 점 4개, 정비 시점 세로선이 보인다.

막히면 원인을 Claude Code에게 찾게 하는 후속 프롬프트를 준다. 정답은 "정답 보기" 요청이 있을 때만 연다.

```
trend_judgement.md 에서 설비A 진동 3.5를 추세로 판정했거나 정비 시점이 이상하다. 해당 시각 앞뒤 3개 값을 표로 보여 주고, 내가 준 판정 규칙을 그대로 적용했는지 한 줄씩 점검해 줘.
```

## QUIZ

### Quiz 1 — 정비팀을 어디로 보낼까

```json
AskUserQuestion({
  "questions": [{
    "question": "20분 간격 진동(mm/s) 기록이 설비 X는 [1.0 → 1.1 → 0.9 → 3.5 → 1.0], 설비 Y는 [1.0 → 1.3 → 1.7 → 2.2 → 2.9]다. 두 설비 모두 평상 범위 상한은 약 2.1이다. 오늘 정비 인력을 한 팀만 보낼 수 있다면?",
    "header": "Quiz 1",
    "options": [
      {"label": "설비 Y", "description": "임계선을 향해 꾸준히 오르는 추세 — 정비 신호. X의 3.5는 곧 돌아온 노이즈라 기록·관찰"},
      {"label": "설비 X", "description": "최고값 3.5가 Y의 2.9보다 크니 더 위험하다"},
      {"label": "둘 다 같은 위험", "description": "둘 다 상한을 넘었으니 같은 우선순위로 본다"}
    ],
    "multiSelect": false
  }]
})
```

정답: 1번. ① Y는 매 시점 오르며 상한을 넘었고 아직 멈출 기미가 없다 — 베어링의 일생에서 "진동이 추세적으로 상승"하는 ② 단계다. X의 3.5는 다음 시점에 1.0으로 돌아온 한 점으로, 측정 오류나 순간 외란일 수 있다. ② 2번은 원본 모범답안이 감점으로 든 바로 그 실수 — "한 번 높았으니 위험"은 노이즈와 추세를 혼동한 것이다. 3번은 판정 없이 경보만 세는 것으로, 인력을 엉뚱한 곳에 쓴다. ③ 현장에서는 X도 버리지 않는다. 같은 튐이 반복되는지 지켜보고, 반복되면 센서·배선부터 점검한다.

### Quiz 2 — 범위 안에서 오르는 온도

```json
AskUserQuestion({
  "questions": [{
    "question": "용접로봇 감속기 온도가 평상 범위 상한(약 64.6℃)을 아직 넘지 않았지만, 지난 2시간 동안 56℃에서 61℃까지 거의 매 측정 꾸준히 올랐다. 같은 시간 진동은 평상 수준이다. 가장 적절한 대응은?",
    "header": "Quiz 2",
    "options": [
      {"label": "조치 없음", "description": "평상 범위 안이므로 정상이다"},
      {"label": "즉시 라인 정지", "description": "오르고 있으니 고장 직전이다"},
      {"label": "범위 안 상승으로 관찰 강화", "description": "'범위 안 상승'으로 기록하고 측정 주기를 줄여 지켜보며, 진동이 따라 오르면 점검을 앞당긴다"}

정답: 3번. ① ± 2σ는 한 점을 보는 기준이라 범위 안의 완만한 상승은 잡지 못한다. 하지만 꾸준한 상승은 그 자체로 흐름 신호이고, 다변수를 함께 보면 판단이 단단해진다 — 온도가 먼저 오르고 진동이 따라오면 마찰·윤활 문제(추정)를 의심할 근거가 된다. ② 1번은 "범위 안 = 정상"으로 흐름을 무시했다. 2번은 근거가 한 변수의 상승뿐인데 가장 비싼 조치를 택했다. ③ 현장에서는 이런 경우를 경보 등급의 '관찰'로 두고, 휴무일 점검 계획에 미리 올려 둔다.
