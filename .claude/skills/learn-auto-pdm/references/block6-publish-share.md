# Block 6: 배포와 공유 — GitHub Pages와 동료에게 보내기

> **Phase A 시작 시 그대로 출력한다:**
> ```
> 📖 공식 문서: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site · https://cli.github.com/manual/gh_repo_create · https://code.claude.com/docs/en/skills
> ```

## EXPLAIN

### 1. 공개에 쓰는 말

| 용어 | 뜻 |
|---|---|
| 저장소 (repository) | GitHub에 올린 폴더. 파일과 바뀐 기록(커밋)이 함께 남는다 |
| GitHub Pages | 저장소의 `index.html`을 공개 웹 주소(`https://내아이디.github.io/저장소이름/`)로 보여 주는 무료 기능 |
| public / private | 누구나 보는 저장소 / 나와 초대한 사람만 보는 저장소. 무료 계정의 Pages는 public 저장소에서 켠다 |
| 공개 전 점검 | 올리기 전에 비밀값·개인정보·회사 자료가 섞였는지, 출처와 '가상' 표시가 있는지 확인하는 것 |
| 스킬 공유 | 동료가 `npx skills add <GitHub 아이디>/learn-auto-pdm` 한 줄로 이 수업을 설치해 같은 순서로 듣는 것 |

### 2. 파일로 보내기 vs 주소로 공유하기

| 기준 | 메일에 파일 첨부 | Pages 주소 공유 |
|---|---|---|
| 받는 사람 | 내려받아 열어야 한다, 버전이 여러 개로 갈라진다 | 링크 하나로 휴대폰에서도 바로 본다 |
| 수정 | 고칠 때마다 다시 보낸다 | 고치면 같은 주소가 새 판이 된다 |
| 재현 | 어떻게 만들었는지 모른다 | 저장소에 데이터·코드·보고서가 함께 있다 |
| 위험 | 회사 메일 밖으로 나가면 통제 불가 | 공개 범위를 내가 정한다 — 그래서 **공개 전 점검이 필수** |

### 3. 보안 수칙 — 사람이 직접 하는 일

- GitHub 로그인은 Claude Code가 띄운 **일회용 코드**를 브라우저 `github.com/login/device`에 직접 넣고, 다음 화면의 **Authorize**까지 누르는 방식으로 한다. 코드는 약 15분 뒤 만료되니 받자마자 넣는다. 비밀번호·토큰을 채팅창이나 파일에 쓰지 않는다.
- 커밋에는 작성자 이메일이 공개 기록으로 남는다. 개인 이메일 대신 GitHub가 주는 noreply 주소를 쓴다.
- 이 수업 데이터는 가상·공개 보도 자료뿐이라 공개해도 된다. **회사 설비의 실측 로그·도면·사진은 같은 저장소에 넣지 않는다.** 회사 데이터로 다시 해 보고 싶으면 private 저장소를 따로 만든다.
- 공개는 되돌리기 어렵다. 저장소를 지워도 그사이 누군가 복사했을 수 있다. 그래서 점검 결과를 보고 내가 "공개해"라고 말한 뒤에만 올린다.

### 4. 케이스 — 6일차로 넘기는 다리

원본 과정에서 5일차 결과는 6일차 통합 보고서의 "제조 역량" 조각이 된다. 공개 주소가 있으면 6일차 보고서에 링크 한 줄로 근거를 붙일 수 있고, 동료는 같은 스킬로 같은 결과를 다시 만들어 숫자를 대조할 수 있다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
pdm-lab 폴더를 GitHub Pages로 공개할 준비를 해 줘. 공개는 내가 점검 결과를 보고 "공개해"라고 말한 뒤에만 해.

1. 공개 전 점검을 해 줘: ① 비밀번호·토큰·이메일·전화번호 같은 패턴이 있는지 ② 모든 결과물에 "실습용 가상 데이터" 또는 출처 표시가 있는지 ③ data/ 의 CSV가 수업 원본 4개뿐인지 ④ 전체 용량. 결과를 output/publish_check.md 에 적고 채팅에 요약해 줘.
2. README.md 를 만들어 줘: 무엇을 했는지 3줄, 대시보드 주소 자리, 데이터 출처(KMA 강의 저장소 keerhee/kma-auto-genai-3-1 의 data/Day5, 가상 데이터 표시, 도입사례 출처 URL), 결과물 목록, 사용한 프롬프트는 이 수업 learn-auto-pdm 을 따랐다는 한 줄.
3. 동료에게 보낼 공유 메시지를 output/share_message.md 에 써 줘: 대시보드 주소 자리, 핵심 결과 3줄(이상 후보, 정비 시점, 파일럿 1순위), 같은 수업을 설치하는 한 줄.
4. 여기까지 하고 멈춰서 점검 결과를 보여 줘. 내가 "공개해"라고 하면 그때:
   - gh 로그인 상태를 확인하고, 안 되어 있으면 브라우저 로그인용 일회용 코드만 알려 줘. 로그인되면 gh auth setup-git 으로 git 이 gh 로그인을 쓰게 해 줘.
   - git 작성자 정보가 비어 있으면 내 개인 이메일 대신 GitHub noreply 주소를 이 저장소에만 설정해 줘.
   - git 저장소로 만들고 첫 커밋을 한 뒤, 내 계정에 public 저장소 my-pdm-dashboard 를 만들어 올려 줘.
   - GitHub Pages를 main 브랜치 루트로 켜고, 주소가 열릴 때까지 확인해 줘.
   - README.md 와 share_message.md 의 주소 자리를 실제 주소로 바꿔 커밋해 줘.
```

### 확인할 것 (Phase B)

- `output/publish_check.md`에 비밀값·개인정보 패턴 0건, 가상·출처 표시 확인, `data/` CSV 4개, 용량이 적혀 있다.
- 수강생이 "공개해"라고 답한 경우에만: `gh repo view my-pdm-dashboard`가 public 저장소를 보여 주고, Pages 주소가 열리며 대시보드 차트·카드·패널이 모두 보인다.
- `README.md`와 `output/share_message.md`의 주소가 실제 Pages 주소다.
- 공개하지 않기로 했다면 저장소를 만들지 않았고, 로컬 커밋까지만 있다.

막히면 원인을 Claude Code에게 찾게 하는 후속 프롬프트를 준다. 정답은 "정답 보기" 요청이 있을 때만 연다.

```
Pages 주소가 404로 나온다. gh 로 저장소의 Pages 설정(브랜치·폴더)과 최근 배포 상태를 확인하고, index.html 이 저장소 루트에 있는지 점검해서 원인을 찾아 줘. 고치기 전에 무엇을 바꿀지 말해 줘.
```

## 과제와 다음

1. **6일차 조각 만들기** — `output/report.md`의 핵심 요약 3줄과 대시보드 주소를 6일차 통합 보고서의 "제조 역량" 절에 붙인다. 제출물: 통합 보고서 해당 절 1쪽(주소 포함).
2. **우리 설비 감시 설계(원본 보강 실습 A)** — 내 현장 설비 1대를 골라 고장 모드 2~3개 × [센서·측정 주기·판정 기준] 표와 경보 3등급(관찰·점검·정지)별 담당·조치를 쓴다. 모르는 값은 '추정'. 회사 정보이므로 **private 저장소나 사내 문서로만** 남긴다. 제출물: 감시설계표 1장.
3. **내 강의 하나 더** — `/course-forge`를 다시 실행해 다른 Day(예: Day3 경쟁사 재무, Day4 업무 자동화)나 내 업무 주제로 learn 스킬을 하나 더 만든다. 제출물: 새 learn 스킬 저장소 주소와 동료 1명의 수강 후기 한 줄.
