## 실습 MVP 계획

- 데이터: 강의 저장소 `keerhee/kma-auto-genai-3-1`의 `data/Day5/` 4개 파일 그대로(가상 3·실데이터 1, 2026-09-15 08:00~16:00, 20분 간격). 단위 진동 mm/s · 온도 ℃ · 압력 bar · 금액 만원.
- 정답: `assets/answers/pdm_answer.py` → `expected.json` (단위 정리 → 설비별 평균 ± 2σ → 노이즈/추세 판정 → 파일럿 배수·순효과)
- 확인할 핵심 수치 후보 (0단계에서 직접 계산해 정답 메모와 일치 확인):
  - 설비A 진동 이상 후보 1건: 12:40 3.5 (평상 범위 0.09~2.10) → 노이즈
  - 설비B 진동 이상 후보 2건: 15:40 2.2, 16:00 2.9 (평상 범위 0.30~2.08) → 추세
  - 설비B 온도 이상 후보 1건: 16:00 65.1 (평상 범위 50.94~64.62)
  - 단위 혼재 6행: 123.6℉→50.9℃ 외, 1690psi→116.5bar
  - 파일럿 배수: 프레스 2.59 · 도장 1.03 · 차체 0.58 · 조립 0.47 → 프레스 1순위
  - 프레스 순효과(절감률 20%·30% 가정): 연간 정지손실 64,800만원 × 20% = 12,960만원, × 30% = 19,440만원 vs 초기 투자 25,000만원 → 1년 회수 안 됨, 약 1.3~1.9년 회수(추정)
- 대시보드: 설비별 진동·온도 선 차트(평상 범위 띠 + 이상 후보 점 + 정비 시점 표시), 판정 표, 파일럿 배수 막대, 보고서 요약. 외부 서버 없이 `index.html` 한 장.

## 원본과 다르게 정한 곳

- **12시간 → 3시간**: 원본은 인트로 2H + 이론 4H + 실습 4H + 보강 2H. 이론은 블록 EXPLAIN으로 압축하고(Hook·인트로 사례·용어는 필요한 블록에 한 단락씩), 실습 6단계는 Block 1~4에 모두 담는다. ⑤ 분석2와 ⑥ 평가는 산출물이 같은 보고서라 Block 4 하나로 합쳤다.
- **도구**: 원본의 Perplexity(사례)·노코드 툴(처리)·Google Sheets(차트)를 Claude Code 하나로 대신한다. 사례는 웹 검색 대신 원본 `도입사례_실데이터.csv`(출처 URL 포함)를 써서 결과가 사람마다 달라지지 않게 했다. 차트는 Sheets 대신 공개할 `index.html`에 그린다.
- **보강 실습 A(우리 설비 감시 설계)는 넣지 않았다**: 수강생 현장 설비 정보가 필요해 정답 수치로 검증할 수 없고, 회사 내부 정보가 공개 저장소에 섞일 위험이 있다. 후속 learn 스킬(예: `learn-pdm-monitor-design`, 비공개 저장소) 후보로 둔다.
- **보강 실습 B는 Block 5로 넣었다**: 데이터와 숫자 정답(배수)이 있고, 덱 모범답안(프레스 1순위)과 일치해 검증된다. 90일 계획·1페이지 제안서는 시간상 퀴즈와 보고서 한 단락으로 줄였다.
- **배포·공유 블록(Block 6)은 원본에 없다**: course-forge 공통 규칙(만들기 → 배우기 → 배포 → 공유). 원본의 "6일차 통합 보고서 조각"으로 넘기는 다리로 설명한다.

## 위험과 가정

- **정비 시점 판정 규칙을 정해야 한다**: 원본은 "추세적 상승이 시작된 시점"이라고만 한다. 설비B 진동은 15:00(1.0→1.3)부터 연속 상승하지만, 온도는 그보다 이른 12:40(56.7)부터 오르기 시작해 ±2σ 안에서 움직인다(정답 메모: "일부러 그렇게 만들었다"). 4단계 정답 스크립트에서 "연속 N회 상승" 같은 규칙을 정하고, 그 결과를 승인 ②에서 보여 드린다.
- 순효과의 절감률 20~30%는 원본에서도 '추정'이며, 부품비 절감은 데이터가 없어 0으로 두고 "보수적 추정"이라고 적는다.
- in/s 환산은 0.043 × 25.4 = 1.09로, 원본 값(1.08·1.1)과 소수 둘째 자리가 다르다. 확인 수치에는 "약 1.1 mm/s"로 쓴다.
- 수강생 PC에 Python이 `py`로만 잡히는 경우가 있다(이 PC도 같음). Block 0 프롬프트에서 Claude Code가 알아서 찾게 한다.
- GitHub 계정·로그인·공개는 사람이 직접 판단해야 하므로 Block 6에서 보안 수칙(토큰을 화면·파일에 쓰지 않기, 회사 자료 금지)을 EXPLAIN에 넣는다.
